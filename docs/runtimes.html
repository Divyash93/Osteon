Runtimes

Runtimes load an exported skeleton (Spine 4.x JSON, or the .osteon project) plus a libGDX-style .atlas and play it in an engine. Both were written independently from public format documentation and contain no Esoteric Software code.

Unity quick start

  1. Package Manager > Add package from disk > runtimes/unity/com.osteon2d.runtime/package.json.
  2. Export JSON and an atlas into one project folder.
  3. Right-click the skeleton file > Create > Osteon2D > Skeleton Data From Selection.
  4. GameObject > Osteon2D > Skeleton Animation, assign the data and an animation.
var anim = GetComponent<OsteonSkeletonAnimation>();
anim.State.SetMix("Run", "Jump", 0.1f);
anim.Play("Run");
anim.State.AddAnimation(0, "Idle", true, 0);
anim.AnimationEvent += (track, e) => Debug.Log(e.name);

Godot quick start

  1. Copy runtimes/godot/addons/osteon2d into your project's addons/.
  2. Add JSON (or .osteon), .atlas and PNGs to the project.
  3. Add an Osteon2DSprite node; set skeleton_path, atlas_path, skin and animation.
  4. For exported games add *.osteon, *.json, *.atlas to the export resource filters.
$Osteon2DSprite.play("Run")
$Osteon2DSprite.add_animation("Idle", true)
$Osteon2DSprite.set_mix("Run", "Jump", 0.1)
$Osteon2DSprite.animation_event.connect(func(track, name, i, f, s): print(name))

How they were verified

A golden-pose dumper (osteon_golden) writes bone matrices, draw order, colours and world vertices from the C++ engine. The C# and GDScript cores are compared against it, with 0 mismatches on the sample rig and on the CyberCoat project. The Unity engine layer has only been compiled against stand-ins, so shader, importer and MeshRenderer wiring are untested in real Unity. Full details · Research notes
